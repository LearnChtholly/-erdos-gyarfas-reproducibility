Second implementation
---------------------
Source: second_local_option_verifier.cpp
SHA256: 60d19772ba307baa8fd944b2f7a6bd69ece82d4a6eae9bd819ab0a2c43dc99ac

It does NOT use the original generator's recursive safe_add option-generation
DFS, memo table, canonical augmentation, old option list for generation, or
certificate DAG transitions.

For each case it independently:
  1. recomputes capacities from Q and E/special vertex;
  2. builds D_Q using an iterative exact-simple-path stack on Q;
  3. enumerates all capacity-feasible internal label words satisfying the
     necessary distance-2 D_Q condition, without reading the certificate K;
  4. for every endpoint pair and triggered word, builds the COMPLETE local
     lift graph;
  5. checks every F-edge in that complete graph for an alternative simple
     path of length 3, 7, or 15 using an iterative stack, hence detecting
     C4/C8/C16;
  6. canonicalizes an option as (endpoint_i, endpoint_j, internal_label_word)
     and compares the complete set with the static certificate;
  7. discards the certificate DAG and runs a separate memoized exact-cover DP
     that always chooses the smallest uncovered endpoint.

Relaxation direction
--------------------
Every restriction in the second implementation is necessary for a true lift:

* capacity: t_v=d_G(v)-d_Q(v), i.e. 4-d_Q(v), or 5-d_Q(v) for the unique
  E=1 distinguished vertex;
* every Q-edge corresponds to one d_F=1 endpoint token and every token belongs
  to exactly one path component;
* all internal d_F=2 vertices are exhausted exactly by their B-label quotas;
* component trigger: otherwise deleting the path component leaves every
  remaining A-vertex degree 3 and every B-vertex degree at least 3, contradicting
  vertex-minimality; ordinary degree-4 B needs >=2 incidences, the unique
  degree-5 B needs >=3;
* D_Q distance-2 condition: equal labels give C4; a Q simple path of length 2
  or 6 gives C8 or C16 after subdivision;
* local C4/C8/C16-freeness is necessary.

The model deliberately ignores some additional true-lift restrictions, notably
forbidden cycles using multiple path components and larger power-of-two cycles.
Thus
    true lift => second-implementation relaxed solution,
so relaxed UNSAT => true-lift UNSAT.
